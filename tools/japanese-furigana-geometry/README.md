# Japanese furigana geometry asset

This tool generates the compact compound-furigana geometry used by Spicy
Lyrics. It does not ship Jitendex, JmdictFurigana, KANJIDIC, or a dictionary
solver in the extension.

The generator starts with pinned Jitendex `(surface, reading)` geometry from
the solver's strict informed-only lane. This lane requires KANJIDIC-derived
character or curated compound knowledge for every solved part and disables the
solver's arbitrary-reading fallback. It then keeps only pairs that:

- are multi-kanji compounds with more detail than the existing broad-ruby
  fallback;
- are not tagged by Jitendex as a special reading; and
- exactly match one production `kuromoji@0.1.2` token and its reading.

Special readings intentionally remain absent from the asset. An absent exact
pair uses Spicy Lyrics' existing whole-compound ruby, so forms such as
`運命[さだめ]`, `一昨日[おととい]`, and `海女[あま]` are never given a
speculative per-kanji split.

JmdictFurigana is a differential oracle during generation. Only exact
Jitendex/JmdictFurigana geometry consensus is emitted. Disagreement or missing
oracle coverage is recorded in `generated-metadata.json` and uses the safe
broad-ruby fallback at runtime; neither source is treated as absolute truth.

## Regenerating

The default command expects the pinned, ignored research inputs recorded in
`generated-metadata.json`:

```powershell
npm run generate:furigana-geometry
```

Pass `--check` to compare regenerated bytes with the tracked asset and
metadata. Input paths can be replaced with `--jitendex-output`,
`--special-pairs`, `--oracle`, and `--kuromoji-package`.

Measure the retained module cost and a mixed hit/miss lookup loop with:

```powershell
npm run benchmark:furigana-geometry
```
